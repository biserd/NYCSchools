# School research tools and comparisons

The canonical D1 data refreshed through 2026 is exposed by a shared public-data contract in `shared/school-research.ts`, loaded by `server/schoolResearchData.ts`.

- Both MCP lanes (`/mcp/muse`, alias `/mcp/schools`, and legacy `/mcp`) return current `demographics`, `demographics_history`, `enrollment_history`, and `regents` from `get_school_details` and `compare_schools`. Existing input schemas and private-tool authorization remain intact. Search adds enrollment and its demographic reporting year. Legacy `get_school_history` also includes the new history, even when ELA/math history is absent.
- `regents` includes `latest_reporting_year`, `available_reporting_years`, latest `results`, and full available `history`. Each result identifies its exact exam and source reporting year, tested count, 65+ pass rate, 80+ threshold percentage, and mean score. It does not invent an overall pass rate or merge distinct exams. Comparison tools additionally expose one `regents_comparison_reporting_year` and aligned per-school `regents_comparison_results`; missing results stay empty rather than using an older year.
- Demographic school years remain explicit, including null for undated current legacy values. Dated history excludes `legacy-undated`; original undated values remain available through the existing demographics-history endpoint. Zero, null, and source bounds remain distinct. Enrollment includes early grades; K–12 subtotals do not.
- `GET /api/schools/:dbn/research-data` exposes the same contract for the comparison page. The authenticated developer detail endpoint `/api/v1/schools/:dbn` adds these sections and keeps its existing fields. Developer list/detail fields identify assessment, science and demographic years separately. No API-key requirements changed.
- The website comparison page adds a shared demographic school-year selector, enrollment/demographic history chart and exact-value table, plus a Regents reporting-year selector and per-exam comparison. It removes the undated legacy “Regents Pass Rate” row. Existing current demographics and race tables show their per-school reporting years; Economic Need Index is labeled on a 0–100 scale.
- The legacy MCP endpoint supports both 2025-11-25 initialization clients and 2026-07-28 per-request clients. Discovery supplies supportedVersions, resultType, ttlMs, cacheScope and server identity metadata, as required by the [2026 discovery specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/discover.mdx). Result envelopes carry server identity and completion type; response headers reflect modern requests. Initialization notifications require no RPC response. Private favorites still require authentication.

Validation: `npx tsx scripts/school-data-integration.test.ts` applies the real D1 migrations to in-memory SQLite and checks storage → shared service → both MCP payloads, the history tool, developer serialization, HTTP, and rendered comparison markup. Cases include different reporting years, missing 2026 results, older history, genuine zero, suppression, bounded values, early-childhood scoring and distinct curricula. Tests also ensure public research cannot call private favorites. Existing rating, Muse, discovery, survey, pricing and ChatGPT landing checks remain applicable.

No data migration or reimport is required for this integration. Read-only live checks compare tool values against canonical profile and dedicated history/Regents APIs. Preserve current production code before deploying with `npm run deploy`; do not republish the expired staging Worker.
