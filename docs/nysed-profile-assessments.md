# NYSED profile assessments: release and staging handoff

This is an additive profile-data release. It neither updates nor backfills the existing school ratings inputs, school directory, district ELA/math, historical proficiency, or Regents. It does not create school profiles.

## Sources and comparability

- [NYSED 2025–26 School Report Card archive](https://data.nysed.gov/files/essa/25-26/SRC2026.zip), November 19, 2026 release. SHA-256: `39223a547a04d83851300dc3c4b55773093783b1fff55306e61d696454c24252`.
- The bundled dictionary, `SRC2026ReadMe_Group1.pdf` (updated November 18), defines the stable institution ID and location-dependent BEDS number on page 3, and defines the ELA, mathematics, and science assessment rows on pages 6–8. SHA-256: `34f34160a713582ad46935654d3d567c559963ef721e2431124bf9fb38acbbeb`.
- [NYCPS LCGMS directory](https://infohub.nyced.org/in-our-schools/operations/lcgms), November 20, 2026 daily report. SHA-256: `fa7a5ac15e8279c81d846cdc9f94fd2b134623a90f2866719146739cd722a287`. The public report is a UTF-16 HTML table exported with an `.xls` extension.
- The source grain is institution, spring, assessment, and population. We require open LCGMS BEDS → ATS System Code, a unique mapping in both directions, stable NYSED institution ID/BEDS across the two years, borough/sector agreement and an existing canonical DBN. For charters we additionally require the normalized street address to agree with the existing record. We never use a school name to resolve a match. A mismatch is unresolved, not proof that a school moved.
- Science only accepts `Science5` and `Science8`. A percentage is calculated from the archived `NUM_PROF / NUM_TESTED`. The document spells the math codes as `Math3` etc.; the database stores `MATH3`–`MATH8`. Only those regular grade rows are used for charter math. No schoolwide math aggregate is inferred. Charter ELA accepts grades 3–8 and the exact published, non-estimated `ELA3_8` row. An aggregate ELA change also requires the same documented grade set in both periods. No combined or Regents-in-lieu grade rows, alternate assessments, `_SMALL` rows or `_EST` estimates enter a comparison.
- Eligible and tested counts are retained from the same record when public. Published percentages are not used to reconstruct any count. Suppressed values, no test takers, and valid zero proficiency are distinct. A change compares unrounded, exact counts from the same release, definition, school and grade in consecutive years. Earlier source years remain dated; these panels never mix NYCPS and NYSED observations.
- The science comparison uses the official geographic-district aggregate from the same archive, grade, assessment, population and spring year. It is a share of all tested students, not a mean of school rates. There are 128 district observations (32 districts × two grades × two springs). The latest result is compared only when both counts are exact and the verified school BEDS and DBN agree with the reporting district; charter and special-district profiles do not inherit a geographic-district benchmark.

The 238-institution reconciliation is for the published ELA aggregate, not all grade rows. Three additional institutions have a usable grade row without that aggregate. That includes suppressed and zero-tested observations, but not rejected joins.

## Reproduce and verify the release

The workflow follows [the November 2026 refresh](2026-data-refresh.md): source extract, read-only baseline, exact local rehearsal, additive staging import, value-level verification. Run from the repo root with Python 3.11+ and Node 22+.

1. In ignored `.wrangler/nysed-assessments/source`, put `SRC2026_Group1.accdb` from the ZIP, the official LCGMS download saved as `LCGMS-download`, and `staging-schools.json` from a read-only `SELECT * FROM schools ORDER BY dbn` on the isolated staging D1 database. The roster JSON is the query's `results` array. The Windows extraction script uses the installed Microsoft Access ODBC driver in read-only mode. On another host, export the same SQL and column names to UTF-8 CSV with an Access-compatible reader; do not substitute rounded percentages or other data sources.
2. Run the science extraction and rehearsal before extracting charters. Supply the original ZIP to record the checksum and preserve the exact source identity.

   ```powershell
   $work = '.wrangler/nysed-assessments'
   $archive = 'C:/path/to/SRC2026.zip'
   ./scripts/data/export-nysed-assessments.ps1 -Database "$work/source/SRC2026_Group1.accdb" -Phase science -OutDir "$work/source"
   python scripts/data/refresh_nysed_assessments.py --phase science --archive $archive --source "$work/source" --out "$work/science"
   ./scripts/data/export-nysed-assessments.ps1 -Database "$work/source/SRC2026_Group1.accdb" -Phase charter -OutDir "$work/source"
   python scripts/data/refresh_nysed_assessments.py --phase all --archive $archive --source "$work/source" --out "$work/combined"
   python scripts/data/test_nysed_profile_assessments.py
   npm run test:nysed-profile-assessments
   npm run test:ratings
   npm run test:school-data
   npm run check
   npm run build
   ```

3. **Staging only:** verify the database ID is `e48a9ae9-4948-4dae-863a-06f6b026b436`. Capture the legacy row fingerprints first. Use the combined import rather than applying the partial science rehearsal independently; the combined source audit knows which institutions have a conflict in another subject.

   ```powershell
   node scripts/d1/audit-nysed-assessments.mjs --before
   npx wrangler d1 execute nyc-schools-ratings-d1-staging --remote --config wrangler.d1-staging.jsonc --file migrations-d1/0014_nysed_profile_assessments.sql --yes
   npx wrangler d1 execute nyc-schools-ratings-d1-staging --remote --config wrangler.d1-staging.jsonc --file .wrangler/nysed-assessments/combined/import.sql --yes
   npx wrangler d1 execute nyc-schools-ratings-d1-staging --remote --config wrangler.d1-staging.jsonc --file migrations-d1/0015_nysed_district_science.sql --yes
   npx wrangler d1 execute nyc-schools-ratings-d1-staging --remote --config wrangler.d1-staging.jsonc --file .wrangler/nysed-assessments/combined/district-science-import.sql --yes
   node scripts/d1/audit-nysed-assessments.mjs --after
   ```

   The rehearsal runs the imports twice, verifies unique grains, source values and foreign keys, and expects no duplicate facts. The stage audit verifies imported values and fingerprints every row and column of the canonical school, historical proficiency and Regents tables. For an existing staging installation of PR #4, apply only `0015` and the district science import before deploying the updated Worker.

4. With the built assets and verified staging export, run `npx tsx scripts/preview-nysed-assessments.ts`. Port 8801 shows the baseline; port 8802 shows the additive panels. Both are local, read-only, noindex previews. An optional `staging-profile-metadata.json` results array from `school_profile_metadata` preserves legacy date labels in the fixture.

5. For an approved production release, verify `wrangler.jsonc` binds `nyc-schools-ratings-production` (`35237f81-df27-4908-be1a-1226faf501e0`). Use the same four reviewed migration/import files from step 3, but only after `node scripts/d1/audit-nysed-assessments.mjs --before --production` verifies the production roster and saves the original fingerprints. Run `node scripts/d1/audit-nysed-assessments.mjs --after --production` before deploying the Worker. Do not use a broad migrations or schema push command. The companion classroom release has its own [audit](classroom-data-pilot.md#release-verification-and-rollback).

## Rollback

Rollback is normally code-only: restore the previous Worker version and leave the additive tables in place. For a separately approved data rollback, verify the exact target and review the generated `combined/rollback.sql`; it deletes only the named release's district benchmark and school facts, then that release row. Never reset or restore the whole database for this release.
